# Compilazioni native su GitHub
Richiesta esplicita dell’utente: compilare direttamente da GitHub senza EAS Build. Expo resta il framework e genera i progetti nativi; Gradle su Ubuntu e Xcode su macOS producono AAB/IPA. Repository dedicato privato gianpaolobol/random-stranger, separato da Fungo Italia e Balotta.
Workflow demo: test e TypeScript, prebuild senza servizi Expo, firma con credenziali nei soli GitHub Actions Secrets, artefatti privati a breve durata, caricamento TestFlight diretto facoltativo via strumenti Apple. Niente token Expo richiesto dal workflow. Google Play resta in test interno e richiede prima creazione app e upload iniziale; non dichiarare una pubblicazione automatica già attiva.
Build native abilitate soltanto dopo verifica quote GitHub e configurazione credenziali; nessun upgrade o abbonamento aggiuntivo. Guard ENABLE_NATIVE_CI evita avvii prematuri. Numeri build distinti da quelli EAS già usati, incrementati anche ai retry. Nessun segreto nel codice o nei log. La build EAS già avviata non viene duplicata per il solo cambio di pipeline.
Alternativa scartata: avviare EAS da GitHub, perché continuerebbe a compilare sui server Expo. La pubblicazione web Sites resta separata.
